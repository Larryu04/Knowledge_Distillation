## ⚠️ Critical Constraints
- **CRITICAL RULE:** All automated dataset generation, evaluation, and OpenAI API calls MUST strictly use `gpt-4o-mini`. The use of `gpt-4o` is explicitly forbidden across the entire project due to extreme cost differences and strict 30k TPM rate limits. Always verify that scripts default to `gpt-4o-mini` and that generation commands explicitly include the `--model gpt-4o-mini` flag.

## 1. Goal
- Fine-tune a **Hebrew CS academic tutor** ("Student" LLM) with **4-bit NF4 QLoRA**.
- Training data = GPT-generated Q&A grounded in **syllabi of Academic College Ramat Gan** (**23 courses** as of 2026-09-30: original 6 → 12 on 2026-09-27 → 23 for v8 — see §4).
- Base: `dicta-il/dictalm2.0-instruct` (Mistral-7B, Hebrew tokenizer). Hardware: **RTX 4070 Super, 12 GB** (also drives the Windows desktop).
- Top priority: **Hebrew robustness** (no language drift to Chinese/Spanish, no EOS loops). Earlier 3B attempt collapsed.
- Output style the model must learn: numbered step-by-step rationale, then a line starting `תשובה סופית:`.

## 2. Strict data format (DO NOT deviate)
Dataset file: **`merged_all_courses.json` = flat JSON list, 27,600 rows (1,200 per course × 23 courses)** — the current training corpus as of 2026-09-30 (v8), superseding `merged_12_courses.json` (14,400 rows / 12 courses, v7) and `merged_6_courses_new.json` (7,200 rows / 6 courses, v6); both kept on disk for history. Every row has **exactly these 5 keys**, all **strings**:

```json
{
  "course_name": "מבוא לתקשורת נתונים",
  "domain": "Computer Networks",
  "instruction": "<Hebrew question>",
  "rationale": "1. ... 2. ... 3. ... (3-5 numbered points, incl. a concrete 'לדוגמה' example or code)",
  "output": "<short synthesized final answer, NOT a copy of rationale point 1>"
}
```
- `set(keys) == {course_name, domain, instruction, rationale, output}` — no extra/missing keys (validators reject).
- `domain` ∈ {Computer Networks, Cybersecurity, Operating Systems, C++, Java, Python, Data Structures, Algorithms, Computer Architecture, Databases, Automata Theory, Software Engineering, Discrete Mathematics, Logic and Set Theory, Graph Theory, Computability and Complexity, Introduction to Cryptography, Introduction to AI, Introduction to Machine Learning, Deep Learning, AI-Based Software Development, Information Systems Foundations, Computational Biology Applications}; `course_name` must match the course exactly:
  Networks=מבוא לתקשורת נתונים · Cyber=מבוא לסייבר · OS=עקרונות מערכות הפעלה · C++=מבוא למדעי המחשב · Java=תכנות מונחה עצמים בשפת Java · Python=תכנות מתקדם בשפת פייתון · Data Structures=מבני נתונים · Algorithms=אלגוריתמים · Computer Architecture=ארגון המחשב ושפת סף · Databases=בסיסי נתונים · Automata Theory=אוטומטים ושפות פורמליות · Software Engineering=שיטות בפיתוח תוכנה · Discrete Mathematics=מתמטיקה בדידה · Logic and Set Theory=לוגיקה ותורת הקבוצות · Graph Theory=תורת הגרפים · Computability and Complexity=חישוביות וסיבוכיות · Introduction to Cryptography=יסודות תורת ההצפנה · Introduction to AI=מבוא לבינה מלאכותית · Introduction to Machine Learning=מבוא ללמידת מכונה · Deep Learning=למידה עמוקה · AI-Based Software Development=פיתוח תוכנה מבוסס בינה מלאכותית · Information Systems Foundations=יסודות מערכות מידע · Computational Biology Applications=יישומים בביולוגיה חישובית.
- Validation (in `generate_pilot_full-dataset.py`): instruction ≥15 chars; rationale has 3-5 numbered points (`1.`–`5.`) + a worked example marker; output ≥30 chars; no forbidden (out-of-syllabus) terms; near-duplicate instructions rejected.
- `course_name` / `domain` are **metadata only** — `train.py` never feeds them into the prompt; `domain` drives the stratified val split.
- Legacy V1/V4 datasets used a different 3-key capitalised schema (`Instruction/Rationale/Output`); **don't mix the two**.
- Generation: `generate_pilot_full-dataset.py` (**gpt-4o-mini only** — see Critical Constraints above; batch-launched by `run_batches.ps1`, logs in `logs/`), `generate_pilot_dataset_for_92.py` (benchmark; replaces the deleted `generate_pilot_dataset_for_48.py`). Per-course output in `raw_courses_data/*.json` (**23 files**, 1,200 rows each); merged via `merge_datasets.py` (`SOURCES` lists all 23 files + expected domain; validates keys/domain/dedup, `--min-per-domain` guard against a short run) → `merged_all_courses.json`.
- Eval sets: **`hebrew_cs_pilot_dataset_92.json` = the OFFICIAL gold benchmark as of 2026-09-30** (4/domain × 23 domains, lowercase 5-key schema, syllabus-derived, `gpt-4o-mini`; scored by `evaluate_models.py`). Superseded: `hebrew_cs_pilot_dataset_48.json` (12 domains, official 2026-09-27 to 2026-09-30, v7 results), which itself superseded the prior 24-item/6-domain pilot set (`hebrew_cs_pilot_dataset_24.json`, now historical — was official 2026-09-20 to 2026-09-27, still valid for the original 6 domains but incomplete for the other 6). `hebrew_cs_eval_dataset_24.json` = **DEPRECATED** (generic CS questions, not syllabus-derived; only the historical v4/v5 benchmark — don't use it for new evaluations) ⊂ `hebrew_cs_eval_dataset_100.json` (eval-only, **never train on it** — leaks into the benchmark).

## 3. Training / eval config (train.py, v8 — uncommitted working copy)
- Out dir `out/dictalm2-tutor-qlora-v8` (**final adapter**; v6/v7 kept for history). LoRA r=16 / α=32 / dropout 0.05 on attn+MLP; **embed_tokens & lm_head frozen**.
- LR 1e-4 cosine, 2 epochs, **effective batch 16** (micro-batch 2 × accum 8, see §4), max_grad_norm 0.3, NEFTune α=5, **`MAX_SEQ_LEN=960`** (23-course corpus with the 23-subject preamble, measured 2026-09-30: tok p50 696 / p99 821 / max 1079; 960 drops 1 outlier row, 872 would drop 43).
- Prompt tokens masked (`labels=-100`); PAD ≠ EOS; explicit EOS in every label; **`PREAMBLE` byte-identical in `train.py`, `inference.py` and `evaluate_models.py`** (updated 2026-09-30 to name all 23 subject areas, ~88 tokens longer than v7's; `evaluate_models.py` had still carried the 6-course preamble through the v7 eval — fixed).
- `DATA_PATH = merged_all_courses.json`. `by_domain`/`domain_weights`/`macro_domain_loss` read `domain` straight off each row — **nothing in `train.py` hardcodes the course list**. Stratified per-domain val split (`MIN_VAL_PER_DOMAIN=20`), early stopping on macro per-domain loss; corpus is exactly balanced → plain shuffle (no weighted sampler).
- Eval: `evaluate_models.py` — masked teacher-forcing loss, base vs adapter, per domain + optional blind A/B CSVs (`--skip-generation` = loss only). Its `DOMAINS` list (23) **is** hardcoded and asserted by the loader — update it with any new course. Default `ADAPTER_DIR=out/dictalm2-tutor-qlora-v8/adapter`, `EVAL_PATH=hebrew_cs_pilot_dataset_92.json`; **output dir is derived from the adapter path**: `eval_results_v8/` for `CURRENT_VERSION`, `eval_results_<vN>_fair/` for older adapters (re-scored with the current preamble). `compare_loss_results.py` merges N `loss_results.csv` files (`--run NAME=PATH`, default v6/v7/v8), domains read from the CSVs, prior/new grouping from `--prior-train-data` (default `merged_12_courses.json`) → `eval_results_v8/v6_vs_v7_vs_v8_comparison.csv`. `inference.py` also points at v8. Results in `summary.md` (§9 v6, §10 v7, **§11 v8**).
- Env: use `.venv\Scripts\python.exe` (Python 3.13). Bare `python` = msys2 3.14 with no ML wheels. Stack: torch 2.6.0+cu124, transformers 5.16.1, peft 0.20, bitsandbytes 0.50.2.
- `train.py` prints are forced to UTF-8 (`sys.stdout.reconfigure`) so redirecting output to a log file on Windows doesn't crash on Hebrew (cp1252 `UnicodeEncodeError`).
- Adapter knowledge: v6 = original 6 domains; v7 = 12; **v8 = all 23 (current/final)**.
- **Deployment:** the CoreCS desktop app (sibling folder `C:\Users\Larry\corecs`, Tauri UI + Rust core + llama.cpp `llama-server` sidecar; status in `corecs/docs/project_memory.md`) runs the tutor fully offline from a Q4_K_M GGUF. Verified end-to-end with **v7** (~93 tokens/s on Vulkan, RTX 4070 SUPER); NSIS installer builds (18.5 MB, model shipped separately). **v8 exported and loaded in CoreCS on 2026-10-01** (`%APPDATA%\com.corecs.app\models\corecs-v8-q4_k_m.gguf` + `.corecs.json` profile with the 23-subject preamble), via `python ..\corecs\scripts\export_gguf.py --adapter out/dictalm2-tutor-qlora-v8/adapter --name corecs-v8`.

## 4. Changelog of solved issues (newest last)
- **V4 dataset cleaning** — removed CJK chars spliced into Hebrew, empty row, leftover "במצגת" slide refs, duplicate instructions (7,449 → 7,431 rows).
- **Domain-imbalance hypothesis tested & rejected** (v4-balanced, v5): fixed sampler `num_samples` bug, excluded "Uncategorized" from the metric, patience 3→5, per-domain eval floor, versioned `OUTPUT_DIR`. Both balanced runs still lost to the plain 09-10 run → not a sampler problem.
- **Real root cause found (09-14):** train/eval **style mismatch** — old training rationales were short (2-3 generic bullets, no examples); eval rationales long (3-5 dense bullets with worked examples). Fix = regenerate corpus with a richer teacher prompt → `merged_6_courses_new.json`.
- **`train.py` syntax error** (stray `0` after `TrainingArguments,`) — removed.
- **JSON list-coercion bug** — GPT returned a field (usually `rationale`) as a JSON *array* → `.strip()` raised `AttributeError` and crashed a generation run. Fixed in both generators: `generate_pilot_full-dataset.py::coerce_string_fields` (list → `"\n".join`, runs before validation so the numbered-point check turns it into a normal retry) and `generate_pilot_dataset_for_24.py::validate_example` (list → `" ".join`).
- **Obsolete keyword classifier removed** — `classify_domain` / `DOMAIN_KEYWORDS` (imported from `evaluate_models.py`; ~59% of rows fell into "Uncategorized") deleted. Domain now read straight from each row's `domain` key.
- **VRAM / BSOD hardware crashes (v6) — ✅ SOLVED & CONFIRMED (2026-09-20): the full v6 run completed 856/856 steps, including the step-107 eval/save that killed the earlier run, with no crash; Windows logged no Kernel-Power 41 / `nvlddmkm` / bugcheck events for the run.** Two crashes on 09-18: a hard OS freeze, then a BSOD `KMODE_EXCEPTION_NOT_HANDLED` (0x1E, kernel access violation) in `nvlddmkm.sys`.
  - **Root causes (chain):**
    1. **Longer sequences — measured.** `merged_6_courses_new.json` is ~2.3× longer per row than V4 (tok p50 565 / p99 707 / max 822 vs 241 / 331 / 444). At batch 8 the worst-case micro-batch peaks at ≈ **11.1 GB** allocated (extrapolated from 5.47 GB @ batch 1, 6.27 GB @ batch 2) on a 12 GB card that also drives the desktop → **VRAM overcommit**.
    2. **Spill into system RAM — inferred, not directly captured.** During the crashed run Python showed **14.9 GB** and system RAM 81% of 31 GB; under the fixed config Python holds only 0.9–1.6 GB working set. Consistent with WDDM demoting GPU allocations to shared system memory (the Windows shared-GPU-memory counter could not be read to confirm).
    3. **`paged_adamw_8bit` crashed the driver during eval/save — strongest lead, inferred.** The crashed run died while writing its first checkpoint (step 107, 09-18 5:42:49 PM, same second as an `nvlddmkm` Error event): `optimizer.pt` was 0.3 MB vs ~86 MB healthy, no `scheduler.pt` / `rng_state.pth` / `trainer_state.json`. Paged optimizers keep state in CUDA unified memory, which Windows/WDDM can't page; `torch.save` reading it under VRAM pressure is the likely trigger. v4/v5 used the same optimizer without issue but were not under memory pressure.
  - **Mitigations now active in `train.py`:** `PER_DEVICE_BATCH=2` × `GRAD_ACCUM=8` (effective batch 16 unchanged, so LR/schedule stay comparable to v4/v5) · `EVAL_BATCH=2` · `set_per_process_memory_fraction(0.85)` (~10.2 GB cap → catchable OOM instead of driver overcommit) + allocator GC config · worst-case-batch preflight fwd/bwd before training (measured 6.27 GB peak) · `adamw_bnb_8bit` instead of paged · `MAX_SEQ_LEN=832` (nothing dropped; don't go lower — 640 drops ~5% of the long, eval-style rows) · `find_resumable_checkpoint()` replacing `get_last_checkpoint` (skips checkpoints with missing files, a truncated `optimizer.pt`, or a different micro-batch size read from `trainer_state.json`; Trainer 5.16 saves in place, so a crash mid-save leaves partial folders). LoRA / 4-bit config deliberately untouched so v6 stays comparable.
  - Partial crash checkpoint kept as evidence at `out/_crashed/v6-checkpoint-107-partial` (adapter weights intact, optimizer state gone). Est. ~13 s/step, 856 steps ≈ 3 h.
